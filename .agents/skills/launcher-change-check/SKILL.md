# 改修後の検証と配布確認

変更したソースが、作品生成・表示・配布版のどこへ影響するかを確認し、必要な検証と反映を選ぶ。テスト成功、ビルド成功、配布先の更新、作品データの更新を別々の結果として扱う。

## 変更と反映先を把握する

- 対象プロジェクトの [AGENTS.md](../../../AGENTS.md) を読む。以下のパスはそのプロジェクトルートを基準にする。
- 依頼内容と現在の差分・該当ソースから、今回確認する変更を特定する。既存の別作業の差分を巻き戻したり、全変更を今回の改修と決めたりしない。
- 「展示用に反映」は、ランチャー本体、Pythonの実行用EXE、作品データのどれかを見分ける。不明なら「画面の修正ですか、作品一覧の更新ですか」など具体的に確認する。
- 調査・修正・検証・ビルド・配布先更新のうち、依頼に含まれる範囲を確認する。必要な反映先と手順を具体化し、既に許可された操作は再確認しない。本番作品の更新まで依頼されたと推測しない。

## 変更に関係する境界を確認する

| 変更内容 | 確認する接点 |
| --- | --- |
| CSV読込・作品形式・設定生成 | `build_works_from_csv.py`、列マッピング、生成設定、増分判定、対応テスト、Electronの読込・表示 |
| 表示・テンプレート・デザイン | `renderer/`、`templates/`、HTML生成処理、開発版と配布版の参照先、既存紹介画面の再利用 |
| IPC・作品起動 | `main.js`、各preload、renderer／テンプレートの呼出側、引数・戻り値、エラー表示・ログ |
| ローカルHTML | 入口の解決、静的配信、パス・ZIP検証、通信制限、ウィンドウとサーバーの終了処理 |
| マニフェスト・本番切替 | 生成側と検証側、バックアップ、コピー後の検証、失敗時の復旧、Windowsのファイルロック |
| パッケージ対象・資源配置 | `package.json` の `files`・`extraResources`、資源パス、各 `build.ps1` のコピー対象と出力先 |

作品形式の変更はPythonの生成設定とElectronの利用側を両方確認する。設定キーの型・大文字小文字・パス・改行変換と、既存作品への互換性を確認する。実行版に必要なファイルがパッケージへ含まれるかも調べる。

## 検証を選んで実施する

- コマンドは現在の定義を確認する。Electron側は `exhibition-launcher/` の `npm test`、Python側は `exhibition-automation/` の `python -m pytest tests -q` が候補。実際に使用するPythonとpytestの有無を確認する。
- 関連する既存テストを読み、変更が影響する振る舞いを検証する。テストが不足する実質的なロジック変更では必要な回帰確認を追加する。低影響の文書・書式修正に形式的なテストを増やさない。
- UI、EXE起動、本番切替全体は既存の自動テストだけで検証済みとしない。実作品を使う必要がある場合は対象と書換範囲を確認し、可能なら検証用配置で行う。
- HTML確認用の `fixture:install` / `fixture:remove` は開発用worksを変更する。使う場合は配布前に確認用作品を除去する。
- 不具合が見つかれば今回の変更に関係する箇所を直して再確認する。根拠のない全データ削除や再ビルドの繰り返しで解消したことにしない。

## 必要な反映だけを行う

| 反映対象 | 現在の手順と留意点 |
| --- | --- |
| Electronのビルド成果物 | `exhibition-launcher/` の `npm run build`。出力を作る処理であり、これだけで既存 `launcher-win/` が更新されたとは扱わない |
| 配布用ランチャー本体 | `exhibition-launcher/build.ps1`。ビルド後に `launcher-win/` の本体・表示資源を更新する。実行中のプロセスとコピー対象を確認する。配布版設定や既存作品は別に確認する |
| Pythonの実行用EXE | `exhibition-automation/build.ps1`。旧build/distを削除し、5ツールのEXEを生成してスクリプト直下にも反映する。ソース変更だけでEXE更新済みとしない |
| 作品データ | 依頼に含まれる場合のみ、Driveミラーの入力から生成し、ステージング検証・本番反映を行う。これはアプリ本体のビルドとは別の書換作業 |

本体・実行用EXEを反映した場合は、実際の配布先で対象の変更を確認する。必要な素材や設定が足りなければ明示し、仮ファイルで成功したことにしない。ビルド対象にコピー用EXEが含まれていても、現在使わないDrive往復コピーを実行・案内しない。

運用や利用方法が変わる場合は、AGENTS.mdと該当する説明資料を更新し、対応するPDF・PowerPoint版にも旧手順を残さない。実装の一時的な値を恒久ルールへ追加しない。

## 結果を伝える

変更内容と、実施したテスト・手動確認・ビルド・反映を区別して報告する。対象PC・配布先、更新した成果物と設定、未確認の動作、利用者に必要な操作を明示する。生成に成功しただけの状態を「展示PCで動作確認済み」としない。
