# 展示ランチャーの不具合調査

相談の言葉を、入力・生成・反映・表示・起動のどこに問題があるかへ結び付ける。技術名や編集すべきファイルを利用者に特定させず、実際の設定・ファイル・ログから確認する。

## 作業範囲を把握する

- 対象プロジェクトの [AGENTS.md](../../../AGENTS.md) を読み、現在の運用と許可された作業範囲を確認する。以下のパスはそのプロジェクトルートを基準にする。
- 「なぜ動かないか知りたい」は原因調査、「直して」は調査と必要な修正として扱う。原因調査だけの依頼から、本番更新や作品データの削除まで広げない。既に許可された操作は再確認しない。
- 起動に使ったファイル、期待する動作、実際の症状、対象作品やエラーが不足する場合だけ質問する。「どのファイルをダブルクリックしましたか」「全部の作品ですか、一つだけですか」など、答えられる表現を使う。
- ローカルで確認できる設定やバージョンを、先に利用者へ調査させない。接続していない別PCの状況は、このPCの結果から推測しない。
- コピー直後のPCで環境全体が未確認なら、引継ぎ確認の範囲を先に整理する。個別の作品不具合と混ぜて全環境の再構築を勧めない。

## 症状から確認先を選ぶ

「反映されない」が、CSV編集、作品ファイル差替え、画面デザイン、コード修正のどれを指すかを見分ける。「ビルド」も作品構造の生成、PythonのEXE化、Electronの配布版生成を区別する。

| 症状 | 優先する確認 |
| --- | --- |
| 作品がない、非表示、順序が違う | 実際に参照する `works` と作品設定、`visible`・`priority`、CSVの列マッピングと生成処理 |
| CSVや提出ファイルの変更が届かない | ミラー内の入力ファイル、生成先、増分処理、ステージングと本番のどちらを表示しているか |
| EXE作品が起動しない | 作品設定の `type`・`executablePath`、実ファイル、実行時ログ。原因が不明なまま外部EXEを繰り返し起動しない |
| HTML・画像・動画・PDFが表示されない | 作品タイプ、入口やメディアのパス、必要な関連ファイル、生成画面とローカルHTMLの違い |
| デザイン変更が見えない | 開発版／配布版、編集したCSS・テンプレート、`workDisplayHandlingMode` による既存紹介画面の再利用 |
| 生成や本番反映が失敗する | 出力された要点・コード・詳細、設定パス、マニフェスト差分、ファイルロック、バックアップ状態 |

必要な枝だけ調べる。主な参照先は以下。

- 生成: `exhibition-automation/config.json5`、`build_works_from_csv.py`。`skip_build` と `show_in_launcher` の解釈、必要ファイルから生成する `visible`、CSV比較とHTMLソースのfingerprintは現在の処理で確認する。
- 反映: `exhibition-automation/apply_update.py`。整合性検証は問題のあるファイルを特定するために使い、検証成功を作品の起動成功と同一視しない。
- 表示・起動: `exhibition-launcher/main.js`、`preload.js`、`renderer/`、`templates/`、`local-html-server.js`。配布版は `launcher-win/resources/` の資源を確認する。
- ログ: `main.js` の設定と `app.getPath('userData')/logs/`。CLIは表示された標準出力も確認する。必要なエラー周辺を取り出し、無関係なCSV行や個人情報まで報告へ載せない。

## 原因に応じて進める

- 事実と候補を分ける。入力・設定・配置の問題を、根拠なくコードの不具合と決めない。
- 確認のために作品やステージングを丸ごと削除しない。既存データを保持して、該当作品・設定・増分処理を調べる。
- 現在の通常経路は、提出CSV・作品をDriveミラーから読込 → 各PCで生成 → 検証・本番反映。マスターコピー用ツールを対処手順へ追加しない。
- 修正が依頼されていれば原因に関係する箇所を直し、該当テストや再現確認を行う。配布先更新が必要でも、今回の許可範囲に含まれるかを区別する。
- 原因が確定できない場合は、何が未確認で、どの観測があれば絞れるかを示す。根拠が増えない再実行や環境変更を続けない。

## 利用者へ返す

結論を先に伝え、確認できた事実、未確認の点、実施した修正・検証、次に必要な操作を簡潔に説明する。操作案には対象のPC・フォルダ・ファイル、期待する結果、データを書き換える場合の対象を添える。利用者に操作を依頼した場合は、こちらで動作確認済みと報告しない。
